# Spec: Refresh State Contract, Benchmarking, and Backend Cleanup

## Overview
`refresh_deals()` in `backend/app/services/refresh.py` orchestrates OpenWebNinja API calls across four retailer adapters, with caching (`search_cache.py`), monthly quota tracking (`quota.py`), and global rate-limit cooldown (`rate_limit.py`) already minimizing calls. This spec adds the structured `refresh_state` field the retro-arcade design spec (`specs/retro-arcade-ui/design-retro-arcade.md`, Requirement 16) depends on, fixes a cache-correctness bug found while grounding that work, adds call-count/latency instrumentation and a standalone benchmark report, and removes verified-dead code in `matcher.py`.

## Goals
- Expose a structured `refresh_state` enum (plus supporting detail fields) from `refresh_deals()` so the frontend can render the design spec's four-state status line without parsing free text.
- Stop stamping the search cache on transient network failures (timeouts, 5xx, malformed responses) as if they were confirmed empty results.
- Track OpenWebNinja call counts and per-call latency so a standalone benchmark script can report cache hit rate, calls-per-refresh, quota burn rate, and latency.
- Delete verified-dead code in `matcher.py` (`SEARCH_ALIASES` redundant dict, unreachable `SKIP_RETAILERS_FOR_KEYWORDS` entries).

## Non-Goals
- No change to the adaptive-TTL strategy — current 8h TTL / ~3-calls-per-day-per-query baseline stays as-is until the new benchmark produces data justifying a change.
- No change to `KEYWORD_ALIASES` (title-matching aliases) — only `SEARCH_ALIASES` (search-term aliases) is affected.
- No load-testing harness or synthetic traffic generator — the benchmark script reads/report on real instrumentation data, it does not drive artificial refresh cycles against OpenWebNinja.
- No change to `rate_limit.py`'s or `quota.py`'s existing exhaustion/cooldown decision logic — only additive state exposure and call-count tracking.
- No CI integration for the benchmark script — it is a standalone, manually-run tool (per Researcher's answer), not part of the pytest suite.

## Preserved Behavior
1. `refresh_deals()`'s existing return dict keys (`upserted`, per-retailer counts, `alerts_sent`, `used_cache_only`, `skipped_external`, `retry_after_seconds`, `message`, `cache_hits`) must continue to be present with identical semantics — `refresh_state` and its detail fields are additive keys, not replacements.
2. The existing `message` string values/formats (e.g. `"Serving DB cache for {retailers} · '{label}' (live search ≤ ~{n}×/day)"`, `"{which} monthly API quota exhausted · serving cache until next month"`) must render identically — the extraction into `_summarize_refresh()` (Requirement 1) is a structural move, not a text change.
3. `search_term_for_keyword()` and `should_skip_retailer_for_query()` (`matcher.py`) must return identical outputs for every existing keyword after the cleanup in Requirements 20–21 — this is a dead-code removal, not a behavior change.
4. `quota.is_quota_exhausted()`, `quota.mark_quota_exhausted()`, `rate_limit.should_skip_external()`, `rate_limit.mark_rate_limited()` — no changes to their existing logic, parameters, or return values.
5. All four adapters (Amazon, Costco, Walmart, Home Depot) continue to share `OpenWebNinjaAdapter._get()`'s HTTP/quota/rate-limit pipeline unchanged except for the additive `had_error` flag and call-count/latency instrumentation (Requirements 2–4).

## Requirements

### Cache-Correctness Bug Fix
1. `OpenWebNinjaAdapter.__init__()` (`backend/adapters/openwebninja.py:76-81`) gets a new instance attribute `self.had_error: bool = False`, initialized alongside `was_rate_limited`/`was_quota_exhausted`.
2. In `_get()`'s existing generic exception handler (`openwebninja.py:147-149`, currently `except Exception as exc: logger.warning(...); return None`), add `self.had_error = True` before the `return None`. Also add `self.had_error = True` in the non-quota `"status": "ERROR"` payload branch (`openwebninja.py:159-160`, currently `logger.warning("%s %s error payload: %s", ...); return None` after the quota check on that same payload already falls through) — this is the same class of bug: an app-level error payload is not a legitimate empty result, and today it falls through to `refresh_deals()`'s `else` branch exactly like the exception case did. `had_error` is set to `True` in exactly these two places; it is never set anywhere else, and is not reset once a request succeeds within the same adapter instance (an adapter instance is single-use per refresh cycle, constructed fresh each `refresh_deals()` call at `refresh.py:242`).
3. In `refresh_deals()`'s per-adapter branch (`refresh.py:262-274`), insert a new condition before the existing `else` that calls `mark_search_fetched`: `elif adapter.had_error: logger.warning("%s fetch failed (network/parse/error-payload) — not stamping cache, will retry next refresh", adapter_cls.retailer)`. This branch does nothing else (no cache stamp, no append to `quota_hit`/`limited`/`cache_hits`) — the retailer's `SearchFetch` row (if any) is left untouched, so `should_fetch_search()` continues to allow a retry on the next refresh cycle rather than waiting out the full TTL.

### `_summarize_refresh()` Extraction and `refresh_state` Contract
4. Extract the message-building `if/elif` chain currently inline in `refresh_deals()` (`refresh.py:279-321`) into a new pure function `_summarize_refresh(*, fetched: list[NormalizedDeal], cache_hits: list[str], quota_hit: list[str], limited: list[str], retry_after: int, query_key: str, ttl: int, cooldown_seconds: int) -> RefreshSummary`, defined in `refresh.py` above `refresh_deals()`. `RefreshSummary` is a `@dataclass` with fields: `message: str`, `refresh_state: str`, `cache_age_seconds: int | None`, `cooldown_seconds: int | None`, `quota_reset_date: str | None`.
5. `refresh_state` is one of exactly four string values: `"live"`, `"cached"`, `"rate_limited"`, `"quota_exhausted"`. `_summarize_refresh()` determines the value using this fixed precedence (matching the design spec's Requirement 19 ordering, highest first): `quota_hit` non-empty → `"quota_exhausted"`; else `limited` non-empty → `"rate_limited"`; else `fetched` non-empty → `"live"`; else (includes both the `cache_hits`-only case and the "nothing fetched, no cache hits" fallback case) → `"cached"`.
6. Detail field population, exactly one populated per state (the other two are `None`):
   - `"quota_exhausted"` → `quota_reset_date` = the earliest `quota.quota_reset_at(adapter_cls.api_slug)` among the retailers in `quota_hit`, formatted as an ISO date string (`.date().isoformat()`); `cache_age_seconds` and `cooldown_seconds` are `None`.
   - `"rate_limited"` → `cooldown_seconds` = `retry_after` (already computed as `settings.rate_limit_cooldown_seconds` at `refresh.py:311`, or the global-throttle `retry_after` from `rate_limit.seconds_until_allowed()` at `refresh.py:199` when the global skip fires before the retailer loop runs — see Edge Case 3); `cache_age_seconds` and `quota_reset_date` are `None`.
   - `"live"` → `cache_age_seconds` = `0`; `cooldown_seconds` and `quota_reset_date` are `None`.
   - `"cached"` → `cache_age_seconds` = the minimum, across retailers in `cache_hits`, of `(now - search_cache.get_fetch(db, retailer, query_key, country).last_fetched_at).total_seconds()` (i.e., the age in seconds of the freshest cache_hits retailer's row) — computed directly from `SearchFetch.last_fetched_at` rather than derived from `seconds_until_refresh()`, since that function's `effective_ttl` is capped at 3600s per-row when `result_count == 0` (`search_cache.py:58`) and does not reduce cleanly back to an age for a uniform `ttl`. `cache_age_seconds` is `None` if `cache_hits` is empty (the "nothing fetched, no cache hits" fallback case — see Edge Case 4); `cooldown_seconds` and `quota_reset_date` are `None`.
7. `refresh_deals()` calls `_summarize_refresh()` once, in place of the existing inline chain, and merges its four fields into the existing return dict (Preserved Behavior 1) — `message` from `RefreshSummary.message` (identical text per Preserved Behavior 2), plus new keys `refresh_state`, `cache_age_seconds`, `cooldown_seconds`, `quota_reset_date`.
8. Edge case — no API key configured (`refresh.py:193-196`) or global-throttle skip before the retailer loop runs (`refresh.py:197-200`): `refresh_deals()` returns `refresh_state="cached"` for the no-key case (nothing was ever live; serving whatever is already in the DB) and `refresh_state="rate_limited"` for the global-throttle-skip case, with `cooldown_seconds` = the already-computed `retry_after` (`rate_limit.seconds_until_allowed()`, `refresh.py:199`) — both cases bypass `_summarize_refresh()` and set these fields directly, since the retailer loop never runs.

### Quota Call-Count Tracking (Benchmarking)
9. Extend `quota.py`'s existing JSON-backed state (`_STATE_PATH`, `_load()`/`_save()`) with a new top-level key `call_counts: dict[str, dict[str, int]]`, keyed `api_slug → {"YYYY-MM": count}` (current UTC year-month, matching the existing monthly-quota framing in `next_month_start()`).
10. Add `quota.record_call(api_slug: str) -> None`, following the same `_load()`/mutate/`_save()` pattern as `mark_quota_exhausted()`, incrementing the current month's counter for `api_slug` (creating the nested dict/key as needed).
11. `OpenWebNinjaAdapter._get()` calls `quota.record_call(self.api_slug)` immediately **before** issuing the request — right after the `is_quota_exhausted()` precheck passes (`openwebninja.py:107-116`) and immediately before entering the `try:` block that wraps `client.get()` (`openwebninja.py:118-120`) — so a connection-level failure (timeout, DNS failure, refused connection) counts as an attempt exactly like an HTTP-response outcome does. It is not called when the pre-flight guards at the very top of `_get()` (`openwebninja.py:100-116`: adapter disabled, already-rate-limited/quota-exhausted earlier in this same refresh cycle, or the `is_quota_exhausted()` precheck itself) short-circuit before that point — those are deliberate skips, not attempts. This deliberately counts "calls we made" for benchmarking purposes, independent of whatever OpenWebNinja's own billing rules are for failed/errored requests — that vendor-billing question is explicitly out of scope for this counter (see Edge Case 5).
12. Add `quota.get_call_count(api_slug: str, month: str | None = None) -> int` (defaults to current month) for the benchmark script to read.

### Latency Instrumentation
13. `OpenWebNinjaAdapter._get()` starts a `time.monotonic()` timer at the same point Requirement 11's counter fires (immediately before the `try:` block), and stops it at whichever point `_get()` resolves an outcome — including the connection-level exception path, not just the HTTP-response paths. Each resolution appends one line to a new JSONL log file `backend/benchmark_log.jsonl` (same directory level as `quota_state.json`, i.e. `Path(__file__).resolve().parent.parent / "benchmark_log.jsonl"`) with fields: `{"ts": <ISO8601 UTC>, "cycle_id": <str>, "api_slug": <str>, "path": <str>, "latency_ms": <int>, "outcome": <"success"|"http_error"|"timeout"|"quota_exhausted"|"rate_limited">}`. Outcome mapping to `_get()`'s branches: quota response (either the post-response `response_looks_like_quota()` check or the non-quota-check `"status": "ERROR"` payload branch that also now sets `had_error`, per Requirement 2 — the `"status": "ERROR"` branch itself splits: quota-shaped → `"quota_exhausted"`, otherwise → `"http_error"`) → `"quota_exhausted"`; `resp.status_code == 429` → `"rate_limited"`; `httpx.TimeoutException` specifically → `"timeout"`; any other exception (connection error, `raise_for_status()` non-429 error, etc.) → `"http_error"`; a payload returned with no error condition → `"success"`. `cycle_id` is the value described in Requirement 16, read from an attribute set on the adapter instance before `fetch_deals()` is called.
14. Writing to `benchmark_log.jsonl` uses simple file-append (`open(path, "a")`) wrapped in the same try/except-and-log-warning pattern as `quota.py`'s `_save()` — a write failure must not raise or interrupt the refresh cycle.
15. No log rotation/retention logic is added in this pass — the benchmark script (Requirement 16) is responsible for reading whatever history exists; unbounded file growth is an accepted tradeoff addressed only if the benchmark script's own usage reveals it as a real problem.

### Benchmark Script
16. `refresh_deals()` generates `cycle_id = uuid4().hex` once at the top of the function (before the retailer loop). Immediately after constructing each adapter (`adapter = adapter_cls(api_key)`, `refresh.py:242`), `refresh_deals()` sets `adapter.cycle_id = cycle_id` before calling `adapter.fetch_deals(...)`. `cycle_id` is a server-side correlation key for `benchmark_log.jsonl` only — it is not added to `refresh_deals()`'s return dict and is not exposed to API clients.
17. `search_cache.should_fetch_search()` (`search_cache.py:63-81`) takes a new optional keyword parameter `cycle_id: str | None = None` and, when provided, appends one additional line to `benchmark_log.jsonl` per call, with fields `{"ts": ..., "cycle_id": ..., "retailer": ..., "query_key": ..., "may_fetch": <bool>}`, using the same append-and-swallow-errors pattern as Requirement 14. `refresh_deals()` passes its `cycle_id` at the existing call site (`refresh.py:231-237`). This is the only change to `should_fetch_search()` — its existing return value, positional parameters, and `logger.info` call are unchanged (Preserved Behavior).
18. Add a standalone script `backend/scripts/benchmark_report.py`, runnable via `python -m scripts.benchmark_report` from `backend/`, not wired into pytest/CI. It reads `benchmark_log.jsonl`, the `SearchFetch` table (via a real DB session using existing `app.database` session setup), and `quota.py`'s `call_counts` state, and prints a plain-text report with these sections:
    - **Cache hit rate**: `(count of should_fetch_search() log lines with may_fetch=False) / (total should_fetch_search() log lines)` over the log's time range.
    - **Calls per refresh**: total `benchmark_log.jsonl` OpenWebNinja-call entries divided by the count of distinct `cycle_id` values present in the log — exact, not inferred from timestamps.
    - **Quota burn rate**: current month's `call_counts` per `api_slug` from `quota.get_call_count()`, printed as a raw count (no target enforcement — descriptive only, per Researcher's answer that this needs a counter before a target can be set).
    - **Latency**: average and p95 `latency_ms` per `api_slug`, from `benchmark_log.jsonl`, grouped by `outcome` (never blending `"timeout"` durations into the same distribution as `"success"` latencies, since a handful of long timeouts would otherwise make the whole distribution meaningless).
19. Target thresholds documented in the benchmark script's output/docstring: cache hit rate should trend toward **≥85%**; calls-per-refresh should trend toward **0 when the cache is warm** (i.e., steady-state operation with no cold queries). Both targets are informational (printed alongside the measured value) — this spec does not add automated pass/fail gating or alerting on these thresholds.

### Matcher Cleanup
20. Delete the `SEARCH_ALIASES` dict (`matcher.py:34-47`) entirely. Change `search_term_for_keyword()` (`matcher.py:65-67`) to: `return f"{keyword.lower().strip()} deals"` — every existing entry already resolves to exactly this pattern (verified: all 12 dict values equal `f"{key} deals"`), so this is a behavior-preserving simplification (Preserved Behavior 3).
21. In `SKIP_RETAILERS_FOR_KEYWORDS["homedepot"]` (`matcher.py:50-62`), delete the three unreachable raw-keyword entries `"groceries"`, `"coffee"`, `"vitamins"`, keeping only the `"grocery deals"`, `"coffee deals"`, `"vitamins deals"` forms. Verified both call sites (`refresh.py:223`, `matcher.py:150-151`) always pass a value already produced by `search_term_for_keyword()` (i.e., always the `"X deals"` suffixed form), so the raw forms can never match (Preserved Behavior 3).

## Data Flow
1. `refresh_deals()` runs the existing per-retailer loop (`refresh.py:205-274`) unchanged except for the new `had_error` branch (Requirement 3) and the adapter's internal call-count/latency recording (Requirements 11, 13) happening as a side effect of `adapter.fetch_deals()` → `_get()`.
2. After the loop, `refresh_deals()` calls `_summarize_refresh()` (Requirement 4) instead of the current inline chain, passing `fetched`, `cache_hits`, `quota_hit`, `limited`, `retry_after`, `query_key`, `ttl`, and `settings.rate_limit_cooldown_seconds`.
3. `_summarize_refresh()` returns a `RefreshSummary`; `refresh_deals()` merges its fields into the return dict alongside the existing keys (Requirement 7).
4. The mobile/web clients (implementation of that consumption is the design spec's concern, already locked) read `refresh_state` + the populated detail field to render the status-ticker line.
5. Independently of any refresh cycle, `benchmark_report.py` (Requirement 18) is run manually by a developer, reading accumulated `benchmark_log.jsonl` entries and `quota.py` state to print the four-section report.

## Edge Cases
1. When `adapter.had_error` is `True` for one retailer but another retailer in the same refresh cycle fetches successfully, `refresh_state` still resolves via the normal precedence (Requirement 5) using whatever `fetched`/`cache_hits`/`quota_hit`/`limited` ended up populated — the errored retailer simply contributes nothing to any of those lists (Requirement 3), it does not force a specific `refresh_state`.
2. When every retailer in a refresh cycle hits `had_error` (total outage) and none had `cache_hits`, `fetched`, `quota_hit`, or `limited`, `refresh_state` resolves to `"cached"` via the existing fallback (Requirement 5's final case), with `cache_age_seconds=None` (Requirement 6's `"cached"` empty-`cache_hits` sub-case) — the status line reads whatever the null-detail rendering is per the design spec (out of scope here; flagged for the frontend implementation to handle a `None` `cache_age_seconds` under `"cached"` state).
3. When the global throttle (`rate_limit.should_skip_external()`) fires before the retailer loop runs, `retry_after` there comes from `rate_limit.seconds_until_allowed()` (`refresh.py:199`), not `settings.rate_limit_cooldown_seconds` — Requirement 8 uses this pre-loop value directly since `_summarize_refresh()` is never called in this branch.
4. When `cache_hits` is empty but `fetched` and `quota_hit`/`limited` are also all empty (the existing `"No new deals fetched; serving cache"` case, `refresh.py:314`) — this maps to `"cached"` with `cache_age_seconds=None`, same as Edge Case 2. This happens e.g. when every configured retailer was skipped by `should_skip_retailer_for_query()` or had no matching `adapter_cls`.
5. Vendor billing semantics for failed/errored OpenWebNinja calls (does a timeout or 5xx count against the monthly quota on their end) are unknown and explicitly not modeled — `quota.record_call()` counts every network call attempt regardless of outcome, purely for our own benchmarking visibility, and is not asserted to match OpenWebNinja's actual billed-request count.
6. `benchmark_log.jsonl` write failures (disk full, permission error) are logged as a warning and swallowed (Requirement 14) — a benchmarking side-channel must never fail a refresh cycle.

## Acceptance Criteria
- [ ] `OpenWebNinjaAdapter` has a `had_error` attribute, set on both the generic-exception path and the non-quota `"status": "ERROR"` payload path in `_get()`.
- [ ] A refresh cycle where an adapter's `_get()` raises an exception, or receives a non-quota `"status": "ERROR"` payload, does not call `search_cache.mark_search_fetched()` for that retailer, and that retailer's cache TTL clock is unaffected (verified: `SearchFetch.last_fetched_at` unchanged).
- [ ] `refresh_deals()`'s return dict includes `refresh_state` (one of the four defined values), `cache_age_seconds`, `cooldown_seconds`, `quota_reset_date`, with exactly one non-`None` detail field matching the active state.
- [ ] All existing `message` string outputs are byte-identical to their pre-refactor values for equivalent inputs.
- [ ] `quota_state.json` gains a `call_counts` section that increments once per OpenWebNinja call attempt, including connection-level failures (timeouts, DNS errors) that never reach an HTTP response — verified across `"success"`, `"http_error"`, `"timeout"`, `"quota_exhausted"`, and `"rate_limited"` outcomes.
- [ ] `benchmark_log.jsonl` accumulates one entry per OpenWebNinja call with `cycle_id`, `latency_ms`, and `outcome`, and one entry per `should_fetch_search()` call with `cycle_id` and `may_fetch`.
- [ ] `benchmark_report.py`'s "calls per refresh" figure is computed from distinct `cycle_id` counts, not from timestamp-proximity grouping.
- [ ] `python -m scripts.benchmark_report` runs standalone (no pytest/CI dependency) and prints all four report sections without raising when the log files are empty or missing.
- [ ] `matcher.py`'s `SEARCH_ALIASES` dict no longer exists; `search_term_for_keyword()` returns identical output to the pre-cleanup version for all 12 existing keywords.
- [ ] `SKIP_RETAILERS_FOR_KEYWORDS["homedepot"]` contains only the three `"X deals"` entries; `should_skip_retailer_for_query()` returns identical output to the pre-cleanup version for all existing call sites.

- `backend/app/quota.py` — add `call_counts` state, `record_call()`, `get_call_count()`.
- `backend/app/search_cache.py` — `should_fetch_search()` gains one additive `benchmark_log.jsonl` append; no other change.
- `backend/app/matcher.py` — delete `SEARCH_ALIASES`, simplify `search_term_for_keyword()`; delete three dead entries from `SKIP_RETAILERS_FOR_KEYWORDS["homedepot"]`.
- `backend/scripts/benchmark_report.py` — new standalone benchmark report script.
